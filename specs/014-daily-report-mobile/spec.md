# Feature Specification: 日报手机端 H5 适配（一期）

**Feature Branch**: `014-daily-report-mobile`
**Created**: 2026-07-04
**Status**: Draft
**Input**: User description: "日报手机端 H5 适配：在现有 ruoyi-ui 中新增 /m 移动路由子树，实现移动登录 + 填写/保存当天日报 + 请假/倒休/年假登记（一期），后端零改动复用 /project/dailyReport/** 接口"

## 背景

驻场人员在客户现场通常没有电脑，现有日报填写页面（`write.vue`）是桌面双栏布局（左侧月历 + 右侧项目列表），在手机浏览器上无法正常使用。导致驻场人员日报填写不方便、不及时。

本特性为一期（MVP）：让驻场人员用手机浏览器打开一个网址、用现有账号密码登录、完成当天日报的填写与保存（含请假登记）。历史回看、统计报表为后续二期/三期，不在本特性范围。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 手机登录并填写保存当天日报 (Priority: P1)

驻场人员在手机浏览器打开系统移动端地址，用现有工号/密码登录（含验证码），看到今天的日报填写页：自己参与的项目列表以卡片形式呈现，每个项目可填工时和工作内容；有子任务的项目可展开按任务分行填写（含工作任务类别）；填完点保存，看到成功提示，当日总工时实时汇总显示。

**Why this priority**: 这是驻场人员的刚需和本特性的存在理由。没有它，其余功能无意义。

**Independent Test**: 手机浏览器（或桌面浏览器移动仿真）访问移动端地址 → 登录 → 对至少一个普通项目和一个含子任务项目填写工时与内容 → 保存 → 重新进入页面数据回显正确；桌面端 write.vue 打开同一天，数据一致。

**Acceptance Scenarios**:

1. **Given** 驻场人员有有效账号且是某项目成员, **When** 手机打开移动端地址并完成登录, **Then** 进入今天的日报填写页，展示其参与的全部项目
2. **Given** 项目无子任务, **When** 填写工时（0.5 小时步进）与工作内容并保存, **Then** 提示保存成功，总工时更新，重新进入回显一致
3. **Given** 项目有子任务（hasSubProject=true）, **When** 展开项目, **Then** 按子任务分行显示，每行可填工时、工作内容、工作任务类别（必填）
4. **Given** 当天日报已保存, **When** 修改某条工时后再次保存, **Then** 数据更新（同日重复保存为覆盖更新，不产生重复日报）
5. **Given** 用户为日报豁免白名单成员, **When** 进入填写页, **Then** 显示豁免提示，不显示填写表单
6. **Given** token 过期或未登录, **When** 直接访问移动填写页, **Then** 重定向到移动登录页，登录后跳回

### User Story 2 - 请假/倒休/年假登记 (Priority: P2)

驻场人员当天请假（事假/病假归为"请假"）、倒休或休年假时，在同一填写页添加非工作条目：选类型（请假/倒休/年假）、填小时数、可选备注，与项目工时一并保存。

**Why this priority**: 请假与项目工时共同构成当日 8 小时的完整记录；缺失会导致工时统计不完整。但单独交付 P1 已可满足"填日报"核心诉求。

**Independent Test**: 在移动填写页添加一条"年假 8 小时"并保存 → 桌面端打开同一天，假期条目显示一致；反之桌面端填的假期在移动端回显一致。

**Acceptance Scenarios**:

1. **Given** 今天在可编辑范围内, **When** 点击"添加假期"选择类型并填写小时数, **Then** 条目加入列表，保存后与工时明细一同持久化
2. **Given** 已有一条假期条目, **When** 删除该条目并保存, **Then** 该假期条目被移除
3. **Given** 假期条目与项目工时同时存在, **Then** 总工时汇总 = 工作工时 + 假期小时，满 8 小时显示达标状态

### User Story 3 - 当周补填与编辑约束 (Priority: P3)

驻场人员周中漏填，周内（本自然周周一至周日）可切换到当周任意一天补填；当周之外的日期只读，与桌面端规则一致。

**Why this priority**: 补填是高频真实场景（驻场忙、当天忘填），但最小可用版本可以只支持"今天"。

**Independent Test**: 移动端切换到本周内昨天 → 可填写保存；经 URL 直达携带上周任一日期 → 页面只读并提示不可编辑（页面内切换入口仅提供本周 7 天，越界日期只能经 URL 到达）。

**Acceptance Scenarios**:

1. **Given** 今天是周三, **When** 切换到本周一, **Then** 可正常填写保存
2. **Given** 经 URL 直达携带上周五日期, **Then** 表单只读，显示"仅可填写本周日报"类提示
3. **Given** 所选日期已有日报, **When** 切换到该日期, **Then** 已填数据回显

### Edge Cases

- 用户不属于任何项目：显示空态提示（"暂无参与的项目，请联系项目经理"），不报错
- 验证码开启（math 型）时移动登录页必须可正常显示验证码图片并输入
- 同一账号桌面端与移动端同时编辑同一天：后保存者覆盖（与现有桌面端多标签行为一致），不做冲突合并
- 弱网/请求失败：保存失败给出明确错误提示，已填内容不丢失（停留在页面可重试）
- 手机上项目很多（>10 个）：列表可滚动，提供项目名称关键字过滤
- 含子任务项目的任务很多：任务行在项目卡片内可折叠/展开
- 软键盘弹起遮挡输入框：输入框获焦时自动滚动到可视区域

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 提供独立的移动端页面入口（URL 路径以 `/m` 开头），手机浏览器访问即可使用，无需安装任何应用
- **FR-002**: 系统 MUST 提供移动端登录页，支持用户名/密码 + 验证码登录，复用现有账号体系与认证接口
- **FR-003**: 桌面浏览器访问 `/m` 路径 MUST 可正常使用（不强制跳回桌面版）；移动设备访问桌面版不做强制跳转（一期仅提供入口地址，引导由使用方通知）
- **FR-004**: 移动填写页 MUST 展示当前用户参与的全部项目（与桌面端 myProjects 数据一致），支持按项目名称关键字过滤
- **FR-005**: 普通项目 MUST 支持填写工时（0–24，0.5 步进）、工作内容与工作任务类别（可多选，与桌面端现行为一致：工时>0 时类别必填）；含子任务项目 MUST 按任务分行填写，每行同样含工时/内容/类别（必填）；类别选项来自字典 sys_gzlb
- **FR-006**: 系统 MUST 支持添加/删除请假、倒休、年假条目（类型来自字典 sys_rbtype 非 work 项），非工作条目记录小时数与可选备注
- **FR-007**: 保存 MUST 与桌面端行为完全一致（同一保存接口）：同日重复保存为覆盖更新；保存后工时汇总、子任务/父项目实际工作量重算由后端完成
- **FR-008**: 页面 MUST 实时显示当日总工时（工作 + 假期），并以视觉状态区分是否达到 8 小时
- **FR-009**: 工时条目编辑约束 MUST 与桌面端一致：仅本自然周（周一至周日）可编辑，非本周日期只读。假期条目一期**窄于桌面端**：随所选日期同受本周约束（桌面端假期支持任意日期提前填写，该能力列入 Out of Scope 二期）。豁免白名单用户显示豁免提示不显示表单
- **FR-010**: 未登录或 token 失效访问 `/m` 下受保护页面 MUST 重定向至移动登录页，登录成功后返回原目标页
- **FR-011**: 移动端 MUST 不影响现有桌面端任何页面的功能与构建产物加载性能（桌面用户不加载移动端专属资源）
- **FR-012**: 后端 MUST 零改动：移动端仅调用既有接口（登录、验证码、getInfo、/project/dailyReport/** 等）

### Key Entities *(数据实体均为既有，无新增)*

- **pm_daily_report / pm_daily_report_detail**: 日报主表/明细，移动端读写与桌面端同一套接口，无 schema 变更
- **字典 sys_rbtype**（日报条目类型 work/leave/comp/annual）、**sys_gzlb**（工作任务类别）：移动端下拉/选择器数据源
- **pm_daily_report_whitelist**: 豁免白名单，决定移动端是否显示填写表单

### Out of Scope（一期明确不做）

- 历史月历回看、跨周历史日报查看（二期）
- 统计/周报/团队报表移动版（三期）
- 桌面端 write.vue 的响应式改造（保持不动）
- 企业微信/微信 OAuth 免密登录、消息提醒推送
- 桌面端"批量填假期"的移动版（一期单条添加即可覆盖需求）
- 提前填写未来日期的假期（桌面端支持任意日期假期；移动端一期仅本周 7 天，提前填年假/婚假仍走桌面端，列入二期）
- 删除整日日报（低频操作，保存覆盖已满足日常修正；需要删除时走桌面端）
- 离线填写/草稿本地暂存

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 驻场人员在主流手机浏览器（iOS Safari、Android Chrome/微信内置浏览器）上，从打开登录页到完成一条日报保存，全程无需横向滚动、无布局错乱，可在 3 分钟内完成
- **SC-002**: 移动端保存的日报与桌面端查看结果 100% 一致（工时、内容、类别、假期条目），反向亦然
- **SC-003**: 现有桌面端所有日报相关 E2E 测试保持通过，桌面端首屏加载资源不因本特性增大
- **SC-004**: 移动填写页在 4G 网络下首次访问可交互时间 ≤ 5 秒；二次访问（哈希资源缓存命中）≤ 2 秒（详见 research.md R1：同 SPA 单入口决策）
- **SC-005**: 触控目标（按钮、输入框、选择器）尺寸符合移动可用性习惯（≥ 44px 高度），软键盘弹起不遮挡正在输入的控件

## Assumptions

- 驻场人员已有系统账号且已被加入相应项目成员；账号开通流程不变
- 移动端地址通过运营方式（通知/二维码）告知驻场人员，一期不做桌面端自动跳转
- 生产环境经既有 Traefik Ingress 暴露，移动端与桌面端同域名同入口，无需新增域名或证书
- 验证码当前为 math 型，移动端沿用；如未来关闭验证码，移动登录页自动隐藏该输入项（与桌面 login.vue 相同的 captchaEnabled 逻辑）
